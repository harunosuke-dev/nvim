# ウィンドウ操作（yabai + skhd）

macOS のウィンドウをキーボードだけで並べ替える。設定の実体は [dotfiles](https://github.com/Harunosuke-web/dotfiles) の `packages/yabai/` と `packages/skhd/` にある。

| ツール | 役割 |
|---|---|
| **yabai** | ウィンドウを自動で敷き詰める（タイル型ウィンドウマネージャ） |
| **skhd** | キーを受け取って yabai に命令を送る |

関連: [tmux の操作](tmux.md)

---

## 階層の対応

Neovim・tmux・yabai は同じ「分割して行き来する」構造を3つの層で繰り返している。

```
yabai   macOS のウィンドウ        Alt + Shift + hjkl
  └─ tmux    端末のペイン          C-b C-hjkl
       └─ Neovim  バッファの分割    C-w hjkl
```

**どの層でも `hjkl` で移動する。** 違いは修飾キーだけ。

---

## 修飾キーの方針

```
Alt + Shift    見るものを変える（フォーカス・レイアウト・アプリ起動）
Ctrl + Alt     ウィンドウを動かす（入れ替え・ディスプレイ送り）
```

**同じ `hjkl` に対して修飾キーだけを変える。** タイル型ウィンドウマネージャの慣習に沿っている。

`Alt` 単独と `Cmd` 系には**何も割り当てていない**。理由は[なぜ Alt 単独を使わないのか](#なぜ-alt-単独を使わないのか)を参照。

---

## フォーカスを移す

| キー | 動作 |
|---|---|
| `Alt + Shift + h/j/k/l` | 左 / 下 / 上 / 右のウィンドウへ |
| `Alt + Shift + Tab` | 直前に使っていたウィンドウへ |
| `Alt + Shift + ,` / `.` | 別のディスプレイへ |

`h/j/k/l` の意味はレイアウトによって変わる。

| レイアウト | 動き |
|---|---|
| **bsp**（タイル） | 画面上の位置関係で移動する |
| **stack**（重ねる） | 位置を無視して全ウィンドウをループ巡回する |
| **中央フロート** | 同上 |

重なった状態では「左のウィンドウ」が存在しないため、順送りに倒している。`h`/`k` が前、`l`/`j` が次。

---

## ウィンドウを動かす

| キー | 動作 |
|---|---|
| `Ctrl + Alt + h/j/k/l` | ウィンドウ自体を左 / 下 / 上 / 右へ入れ替える |
| `Ctrl + Alt + ,` / `.` | ウィンドウごと別のディスプレイへ送る |
| `Ctrl + Alt + i` / `o` | 次に開くウィンドウを右 / 下に入れる |
| `Alt + Shift + [` / `]` | 幅を狭める / 広げる |

フォーカス移動と**同じ `hjkl`** を使う。`Alt + Shift` が「見る」、`Ctrl + Alt` が「動かす」。

---

## レイアウトを変える

| キー | 動作 |
|---|---|
| `Alt + Shift + Space` | **タイル ⇄ 全画面重ね**を切り替える |
| `Alt + Shift + c` | スペースの全ウィンドウを**中央にフロート**させる（もう一度で復帰） |
| `Alt + Shift + f` | フロートレイアウト（自動配置をやめる） |
| `Alt + Shift + e` | 分割比を均等に戻す |
| `Alt + Shift + r` | 90度回す |
| `Ctrl + Alt + m` | 上下と左右を入れ替える |
| `Alt + Shift + m` | Mission Control |

### 全画面で使いたいとき

**`Alt + Shift + Space`** で stack レイアウトにすると、全ウィンドウが画面いっぱいに重なる。`Alt + Shift + h/j/k/l` で切り替えられるので、tmux の `C-b z`（ペインの拡大）と同じ感覚で使える。

### 見比べたいとき

**`Alt + Shift + c`** で全ウィンドウを中央に浮かせる。少し小さめに揃うので、背景を落とした状態で1つずつ確認できる。もう一度押すとタイルに戻る。

## アプリを開く

| キー | アプリ |
|---|---|
| `Alt + Shift + Return` | Ghostty |
| `Alt + Shift + 0` | Brave |
| `Alt + Shift + n` | Notion |

## なぜ Alt 単独を使わないのか

**skhd は OS 全体でキーを横取りする。** アプリごとの除外設定を入れていないため、`Alt + f` を skhd に割り当てると、端末の中で `Alt + f` を押しても skhd が先に奪ってしまう。

実際に次の3つが動かなくなっていた。

| キー | 本来の動作 | 奪っていたもの |
|---|---|---|
| `Alt + f` | zsh のセッション切り替え | yabai のフロートレイアウト |
| `Alt + ,` | zsh の履歴補完 | yabai のディスプレイ移動 |
| `Alt + j` / `k` | tmux のペイン移動 | yabai のフォーカス移動 |

そのため **`Alt` 単独には一切割り当てていない**。端末側が自由に使える。

`Cmd` 系も空けてある。ランチャーなど他の用途のため。

---

## 設定の再読み込み

```sh
skhd --reload      # キー割り当て
yabai --restart-service   # yabai 本体
```

`skhd --reload` はキー割り当てだけを読み直す。ウィンドウの配置ルール（`yabairc`）を変えた場合は yabai 側の再起動が要る。

---

## 注意点

**`Ctrl + 矢印` は使えない。** macOS のデスクトップ切り替えと Mission Control が OS レベルで押さえており、skhd にも届かない。

**スクリプトは bash 3.2 で動く必要がある。** macOS 標準の `/bin/bash` は 3.2 で、`mapfile` などの新しい機能が使えない。

**`--focus west` などは bsp 配置のウィンドウしか対象にしない。** stack レイアウトやフロート中は「対象なし」で失敗する。`focus_dir.sh` がレイアウトを判定して巡回に切り替えている。
