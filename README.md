# nvim

Next.js（TypeScript / React / CSS Modules）での開発を主目的とした Neovim 設定。

- **Neovim 0.12 以降が必須**（`vim.lsp.config` / `after/lsp/` / `vim.pack` などの前提）
- 端末は Ghostty または Alacritty ＋ tmux を想定
- リーダーキーは `Space`

関連: [Vim / Neovim 入門](docs/vim.md) ／ [tmux の操作](docs/tmux.md) ／ [ウィンドウ操作（yabai + skhd）](docs/window.md)

## 構成

```
.
├── init.lua                  リーダーキーの定義と各モジュールの読み込みのみ
├── lua/
│   ├── config/               プラグインに依存しない設定
│   │   ├── options.lua       vim.opt 系
│   │   ├── filetype.lua      拡張子の判定（.mdx など）
│   │   ├── keymaps.lua       プラグイン非依存のキーマップ
│   │   ├── autocmds.lua      自動処理（IME 切替、巨大ファイル対策など）
│   │   ├── commands.lua      :ConfigReload
│   │   ├── highlights.lua    iceberg の配色調整
│   │   └── lazy.lua          lazy.nvim のブートストラップ
│   └── plugins/              カテゴリ単位のプラグイン定義
├── after/lsp/                LSP サーバごとの設定
├── snippets/                 自作スニペット（VSCode 形式）
├── data/                     LSP に渡す補助データ
└── lazy-lock.json            プラグインのバージョン固定
```

### 設計の方針

**キーマップは2箇所に分ける。** プラグインに依存しないものは `config/keymaps.lua`、プラグイン固有のものは各プラグイン定義の `keys = {}` に置く。後者にしないと lazy.nvim の遅延ロードが効かず起動が遅くなる。

**LSP の設定は `after/lsp/` に置く。** Neovim は `runtimepath` 上の `lsp/<name>.lua` をすべてマージするため、nvim-lspconfig が配る既定値と自分の設定が同列に扱われる。`after/lsp/` なら確実に後から読まれ、上書きできる（`:help lsp-config-merge`）。

**プラグインはカテゴリ単位のファイルにまとめる。** 1プラグイン1ファイルにすると数が増えすぎて把握しづらい。

## セットアップ

### 新しい Mac で再現する

```bash
git clone https://github.com/Harunosuke-web/dotfiles ~/.dotfiles
ghq get Harunosuke-web/nvim          # ~/Repos/github.com/Harunosuke-web/nvim へ
~/.dotfiles/scripts/setup.sh          # brew / stow / nvim のリンクまで一括
nvim                                  # プラグインと LSP が自動導入される
```

`setup.sh` の中で `setup-nvim.sh` が `~/.config/nvim` へのシンボリックリンクを張る。

### 前提となる外部コマンド

| コマンド | 用途 | 導入 |
|---|---|---|
| `tree-sitter` | パーサのビルド（**main ブランチでは必須**） | `brew install tree-sitter-cli` |
| `rg` | 全文検索 | `brew install ripgrep` |
| `fd` | ファイル検索 | `brew install fd` |
| `fzf` | 絞り込み | `brew install fzf` |
| `lazygit` | Git クライアント | `brew install lazygit` |
| `node` | LSP サーバの多くが Node 製 | mise |
| `macism` | 日本語入力の自動解除 | `brew install macism` |

LSP サーバと整形ツールは mason が自動導入する。手動操作は不要。

### 設定を変えたときの反映

| 変更した場所 | 反映方法 |
|---|---|
| `lua/config/*.lua` | `:ConfigReload` |
| `after/lsp/*.lua` | `:lsp disable <名前>` → `:lsp enable <名前>` |
| カラースキーム | `:colorscheme <名前>` |
| `lua/plugins/*.lua` の `opts` | **再起動が必要** |
| プラグインの追加・削除 | `:Lazy sync` の後に再起動 |

`:source $MYVIMRC` は効かない。`init.lua` が `require()` で各モジュールを読んでおり、2回目以降は Lua のモジュールキャッシュが返るだけで再実行されないため。`:ConfigReload` はこのキャッシュを明示的に捨てている。

`:lsp restart` だけでは `after/lsp/*.lua` の変更を拾わない（`vim.lsp.config` が解決済みの設定をキャッシュするため）。`restart` はサーバが固まった時の復帰用。

## 使い方

Vim そのものの操作（モード、`d` / `c` / `y` と範囲の組み合わせ、テキストオブジェクト）は [Vim / Neovim 入門](docs/vim.md) にまとめてある。ここではこの設定に固有の使い方を扱う。

### 起動する

引数なしで `nvim` を実行すると起動画面が出る。よく使う操作と、最近の作業への入り口が並ぶ。

| キー | 動作 |
|---|---|
| `f` | ファイルを探す |
| `g` | 全文検索 |
| `s` | セッションを復元 |
| `m` | キーマップ一覧 |
| `u` | プラグインを更新 |
| `q` | 終了 |

下に**最近開いたファイル5件**と**プロジェクト3件**が出る。番号を押せば直接開く。プロジェクトを選ぶとそのディレクトリへ移動し、セッションがあれば一緒に復元される。

`h` `j` `k` `l` は割り当てていない。項目間の移動は通常のカーソル操作で行うため。

ファイル名を指定して開いた場合（`nvim foo.ts`）は起動画面を出さずに直接そのファイルが開く。

### 外部でファイルが変わったとき

**AI エージェントや `git` の操作でファイルが書き換わると、自動で読み直す。** 画面に戻った時・別のバッファへ移った時・手を止めた時に検知する。読み直しが起きた時は通知が出るので、黙って中身が変わることはない。

編集中の内容がある状態で外部から書き換えられた場合は、Neovim が確認を求める。

### コードを読む

**今どこにいるか**は画面上部のパンくずに出る。ディレクトリ階層に加えて、カーソルが今どの関数・クラスの中にいるかまで表示される。

```
 󰉋 app  page.tsx 󰊕 Page
```

`<Space>;` を押すと各要素を選んで直接ジャンプできる。

**定義や参照へ移動する。**

| キー | 動作 |
|---|---|
| `<Space>gd` | 定義へジャンプ |
| `<Space>gr` | 参照一覧 |
| `<Space>gi` | 実装へジャンプ |
| `<Space>gt` | 型定義へジャンプ |
| `<Space>gs` | このファイルのシンボル一覧 |
| `<Space>gS` | プロジェクト全体のシンボル検索 |
| `K` | ホバー（型やドキュメントを表示） |
| `<C-o>` / `<C-i>` | 移動履歴を戻る / 進む |

候補が1件なら即ジャンプし、複数あればプレビュー付きの一覧が出る。

CSS Modules も追える。`styles.title` の上で `<Space>gd` を押すと `page.module.css` の該当クラスへ飛ぶ。

**同じ識別子を見つける。** カーソルを識別子の上に置くと、画面内の同じものが自動で薄くハイライトされる。`]]` / `[[` で次・前へ移動できる。LSP が使える場面では「同じ綴りの別物」を除いた正確な参照だけが光る。

**関数の間を移動する。** `]f` / `[f` で次・前の関数の先頭へ。`]F` / `[F` で末尾へ。

### コードを書く

**補完は打つだけで出る。** 候補が1件目から選択され、確定後の姿が薄い文字で行内に表示される。

| キー | 動作 |
|---|---|
| `Tab` | 確定。スニペットの穴が残っていれば次の穴へ。どちらでもなければインデント |
| `<C-n>` / `<C-p>` | 次 / 前の候補 |
| `<C-e>` | 閉じる |
| `<C-k>` | シグネチャ（引数の説明）を表示 |
| `jk` / `jj` | 挿入モードを抜ける |

補完の候補は LSP・ファイルパス・自作スニペット・バッファ内の単語から集める。

**スニペットは自作分のみ**。`snippets/<filetype>.json` に VSCode 形式で書く。ファイル名がそのまま filetype になり、`all.json` は全ファイルタイプで有効。`typescriptreact` では `typescript` と `javascript` の分も候補に出る。

**タグは自動で閉じる。** `<div>` と打つと `</div>` が入り、開始タグを `section` に書き換えると閉じタグも追従する。

**囲みを操作する。**

| キー | 動作 |
|---|---|
| `ysiw"` | 単語を `"` で囲む |
| `cs"'` | `"..."` を `'...'` に変える |
| `ds"` | `"` を外す |

**構文単位で選択・編集する。**

| キー | 対象 |
|---|---|
| `vaf` / `vif` | 関数（宣言ごと / 中身だけ） |
| `vac` / `vic` | クラス・コンポーネント |
| `vaa` / `via` | 引数 |
| `<Space><CR>` | カーソルを含む構文ノードを入れ子ごとラベル表示し、階層を選んで選択 |

`<Space>an` / `<Space>ap` で引数の順序を入れ替えられる。

**1行と複数行を切り替える。** `<Space>j` で `{ a: 1, b: 2 }` を複数行へ展開し、もう一度押すと畳む。JSX の props でも使える。

**画面内を移動する。** `<CR>` を押して2文字打つと、該当箇所にラベルが出る。そのラベルキーで飛ぶ。

**保存すると自動で整形される。** prettier / stylua / shfmt をファイルタイプごとに使い分ける。プロジェクトに prettier の設定があればそれを尊重する。一時的に切りたい場合は `:FormatDisable`（`!` を付けるとこのバッファのみ）。

### 検索と置換

**探す。**

| キー | 対象 |
|---|---|
| `<Space>ff` | ファイル名 |
| `<Space>fg` | 全文検索 |
| `<Space>fb` | 開いているバッファ |
| `<Space>fr` | 最近開いたファイル |
| `<Space>fw` | カーソル下の単語を全文検索 |
| `<Space>f/` | 現在のバッファ内 |
| `<Space>fR` | 直前の検索を条件ごと復元 |

**検索結果を一覧として残す。** 検索中に `<C-q>` を押すと、ヒットした全件が画面下部の quickfix に送られる。

```
<Space>fg で検索  →  <C-q> で全件を quickfix へ  →  j / k で流し読み
```

quickfix では `j` / `k` で一覧を上下すると、隣のウィンドウが**その場所へ自動で追従**する。内容を確かめながら探せる。

| キー | 動作 |
|---|---|
| `j` / `k` | 一覧を移動（対象位置が追従表示される） |
| `<CR>` | その場所へ移動（フォーカスも移る） |
| `q` | 一覧を閉じる |
| `<C-j>` | 一覧へ戻る（ウィンドウ移動） |
| `<C-o>` | 移動前の場所へ戻る |
| `]q` / `[q` | 一覧を開かずに次 / 前へ |
| `<Space>uq` | 一覧の開閉 |

**置換する。**

| 範囲 | 方法 |
|---|---|
| 現在のバッファ | `:%s/foo/bar/g`（打ちながら結果が分割ウィンドウにプレビューされる） |
| プロジェクト全体 | `<Space>rr` |
| カーソル下の単語 | `<Space>rw` |
| このファイル内 | `<Space>rf` |

`<Space>r*` は検索結果が編集可能なバッファに出るので、対象を選別しながら一括変更できる。

### Git を扱う

**編集中の差分は行の左端に出る。** 変更のある行に印が付き、以下の操作ができる。

| キー | 動作 |
|---|---|
| `]c` / `[c` | 次 / 前の変更箇所へ |
| `<Space>hs` | この変更をステージ（ビジュアル選択中は選んだ行だけ） |
| `<Space>hr` | この変更を取り消す |
| `<Space>hp` | この変更を吹き出しで確認 |
| `<Space>hb` | この行を書いたコミットを表示 |
| `<Space>hd` | 直前のコミットとの差分 |
| `dih` | 変更箇所を丸ごと削除（テキストオブジェクト） |

**コミットや履歴閲覧は lazygit で行う。** `<Space>gg` で開く。`<Space>gG` で現在のファイルのコミット履歴だけを見られる。

役割分担は「編集しながらの細かい操作は行の左端、腰を据えた操作は lazygit」。

### エラーに対処する

**エラーは行の左端と行内に出る。** 深刻なものが優先表示される。

| キー | 動作 |
|---|---|
| `]d` / `[d` | 次 / 前の診断へ |
| `<C-w>d` | 診断の詳細を吹き出しで表示 |
| `gra` | コードアクション（自動修正の候補） |
| `grn` | リネーム（プロジェクト全体の参照が追従する） |

**一覧で潰す。**

| キー | 対象 |
|---|---|
| `<Space>xx` | 診断一覧（プロジェクト全体） |
| `<Space>xX` | 診断一覧（このファイル） |
| `<Space>fd` | 診断を絞り込み検索 |
| `<Space>xt` | TODO 一覧 |

`<Space>x*` は一覧を開いたまま順に潰す用途、`<Space>f*` は絞り込んで1つ選ぶ用途。

**ESLint の自動修正**は `:EslintFixAll`。整形（prettier）とは役割を分けてある。

### ファイルを操作する

`<Space>e` または `-` でファイラを開く。**ディレクトリが編集可能なバッファとして開く**ので、通常の Vim 操作がそのまま使える。

| 操作 | やり方 |
|---|---|
| リネーム | 行を書き換えて `:w` |
| 削除 | 行を消して `:w`（ゴミ箱へ移動するので復元可能） |
| 新規作成 | 行を追加して `:w` |
| 複数を一括 | ビジュアル選択して `dd` / `p` など |

**リネームすると import パスが自動更新される**（LSP 連携）。

| キー | 動作 |
|---|---|
| `-` | 親ディレクトリへ |
| `_` | 作業ディレクトリへ |
| `<CR>` | 開く |
| `<C-s>` | 縦分割で開く |
| `<C-t>` | 新しいタブで開く |
| `<C-p>` | プレビュー |
| `g.` | 隠しファイルの表示切替 |
| `g?` | ヘルプ |

### 作業を中断・再開する

**セッションを保存・復元する。** 開いていたバッファ・分割・カーソル位置がディレクトリごとにディスクへ保存される。PC を再起動してもまたいで復元できる。

| キー | 動作 |
|---|---|
| `<Space>ss` | このディレクトリのセッションを復元 |
| `<Space>sl` | 最後に使ったセッションを復元 |
| `<Space>sd` | 今回は保存しない（一時的な作業用） |

起動時の自動復元はしない（意図せず前回の状態に戻ると混乱するため）。

## キーマップ一覧

`<Space>` を押して少し待つと、そこから続くキーの一覧が出る。以下は主要なものの抜粋。

### なぜそのキーなのか

キーは**英単語の頭文字**から来ている。由来が分かれば、忘れても思い出せる。

| 接頭辞 | 由来 | 意味 |
|---|---|---|
| `f` | **F**ind | 探す |
| `g` | **G**o to | 移動する（`gg` だけは lazygit） |
| `h` | **H**unk | Git の変更のかたまり |
| `r` | **R**eplace | 置換する |
| `s` | **S**ession | セッション |
| `n` | **N**otification | 通知 |
| `u` | **U**I | 表示の切り替え |
| `c` | **C**ode | コード |
| `b` | **B**uffer | バッファ |
| `a` | **A**rgument | 引数 |
| `e` | **E**xplorer | ファイラ |
| `w` | **W**rite | 保存 |
| `q` | **Q**uit | 閉じる |
| `x` | （慣例） | 一覧。trouble.nvim の慣習で、単語の頭文字ではない |

2文字目も同じ規則に従う。

| キー | 読み方 |
|---|---|
| `<Space>ff` | **F**ind **F**ile — ファイルを探す |
| `<Space>fg` | **F**ind **G**rep — 全文検索 |
| `<Space>fb` | **F**ind **B**uffer — 開いているバッファ |
| `<Space>fr` | **F**ind **R**ecent — 最近開いたファイル |
| `<Space>fw` | **F**ind **W**ord — カーソル下の単語 |
| `<Space>fd` | **F**ind **D**iagnostics — 診断 |
| `<Space>fk` | **F**ind **K**eymap — キーマップ |
| `<Space>fc` | **F**ind **C**olorscheme — 配色 |
| `<Space>ft` | **F**ind **T**odo — TODO |
| `<Space>fh` | **F**ind **H**elp — ヘルプ |
| `<Space>fR` | **F**ind **R**esume — 直前の検索を再開 |
| `<Space>gd` | **G**o to **D**efinition — 定義 |
| `<Space>gr` | **G**o to **R**eferences — 参照 |
| `<Space>gi` | **G**o to **I**mplementation — 実装 |
| `<Space>gt` | **G**o to **T**ype definition — 型定義 |
| `<Space>gs` | **G**o to **S**ymbols — シンボル |
| `<Space>hs` | **H**unk **S**tage — 変更をステージ |
| `<Space>hr` | **H**unk **R**eset — 変更を取り消す |
| `<Space>hp` | **H**unk **P**review — 変更を確認 |
| `<Space>hb` | **H**unk **B**lame — 誰が書いたか |
| `<Space>hd` | **H**unk **D**iff — 差分 |
| `<Space>rw` | **R**eplace **W**ord — 単語を置換 |
| `<Space>rf` | **R**eplace in **F**ile — このファイル内 |
| `<Space>ss` | **S**ession **S**elect — セッションを復元 |
| `<Space>sl` | **S**ession **L**ast — 最後のセッション |
| `<Space>nh` | **N**otification **H**istory — 通知の履歴 |
| `<Space>uh` | **U**I **H**ints — インレイヒント |
| `<Space>ub` | **U**I **B**lame — 行ブレーム |
| `<Space>uq` | **U**I **Q**uickfix — 一覧の開閉 |
| `<Space>cf` | **C**ode **F**ormat — 整形 |
| `<Space>bd` | **B**uffer **D**elete — バッファを閉じる |
| `<Space>an` / `<Space>ap` | **A**rgument **N**ext / **P**revious — 引数を入れ替え |

**大文字は変種を表す。** ただし方向はプラグインの慣習に従うため一定ではない。

| キー | 小文字との違い |
|---|---|
| `<Space>gS` | `gs`（このファイル）に対し、**プロジェクト全体**のシンボル |
| `<Space>xX` | `xx`（プロジェクト全体）に対し、**このファイル**の診断 |
| `<Space>hS` | `hs`（この変更）に対し、**ファイル全体**をステージ |
| `<Space>fD` | `fd`（このファイル）に対し、**プロジェクト全体**の診断 |

**Vim の標準的な規則も踏襲している。**

| 規則 | 例 |
|---|---|
| `]` / `[` は「次 / 前」 | `]d` `[d` は次・前の **D**iagnostic |
| `a` / `i` は「まわりごと / 中身だけ」 | `vaf` は関数を宣言ごと、`vif` は中身だけ |
| `g` は「移動」 | `gd` `gg` `gc` |

## カスタマイズ

### LSP サーバを追加する

1. `lua/plugins/lsp.lua` の `servers` に名前を足す（mason が自動で導入する）
2. 詳細設定が要るなら `after/lsp/<名前>.lua` に書く

```lua
-- after/lsp/gopls.lua
return {
  settings = {
    gopls = { analyses = { unusedparams = true } },
  },
}
```

サーバ名は `:Mason` の一覧、または `:lsp enable <Tab>` の補完で確認できる。

### 整形ツールを追加する

`lua/plugins/format.lua` の `formatters_by_ft` にファイルタイプとツールを足し、`lua/plugins/lsp.lua` の `tools` にツール名を足す（mason が導入する）。

### 配色を変える

`lua/config/highlights.lua` の `ICEBERG` テーブルを編集する。5段階の明度で構成されている。

| 用途 | 既定 |
|---|---|
| 本文 | `#0d0e14` |
| 行番号・記号の列 | `#161822` |
| カーソル行・フロート背景 | `#1f2233` |
| フロート内の選択行 | `#292e47` |
| パンくずの文字 | `#7d8296` |

lualine の各要素は `WinBar` の色を読むので、`breadcrumb` を変えれば追従する。

**この調整は iceberg のときだけ適用される。** 他のテーマに切り替えると素の配色になる。

### テーマを切り替える

```vim
:colorscheme tokyonight-storm
```

`<Space>fc` ならプレビューしながら選べる。恒久的に変えるなら `lua/plugins/colorscheme.lua` の `vim.cmd.colorscheme('iceberg')` を書き換える。

導入済み: `iceberg` / `iceberg-light` / `tokyonight`（4種）/ `kanagawa`（4種）/ `github_*`（11種）

## 既知の制限

**MDX の LSP が無い。** `mdx-analyzer` は依存する `vscode-uri` の破壊的変更で起動できない（上流未修正）。`.mdx` は Treesitter のハイライトと prettier の整形までは効く。

**巨大ファイルでは機能が落ちる。** 1.5MB を超えると Treesitter と LSP を無効化し、Vim の正規表現ハイライトに切り替える。色は残り、補完もバッファ内の単語・パス・スニペットは動く。

**日本語入力からの自動復帰はしない。** 挿入モードを抜けた時などに英字へ切り替えるが、逆方向は `macism` が受け付けないため手動で切り替える。

**イタリックには端末側の対応が要る。** tmux では `tmux-256color` が必要。設定変更後は新しいウィンドウを開けば反映される（サーバの再起動は不要）。

**パンくずのメニューの見た目**に未解決の違和感がある。`lua/plugins/ui.lua` に TODO として調査候補を残してある。
